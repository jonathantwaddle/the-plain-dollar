The Plain Dollar — UX / front-end brief

Build a simple, high-trust personal-finance site that feels like a calm answer to “what is the best credit card?” — not like NerdWallet or Bankrate.

Stack is already Astro 7 in this repo. Do not rewrite the data layer, the decision engine, or the /go/{slug}/ click router. Reskin and restructure the UI. Keep existing routes working.

What this site is

A US money site. Named editor: Jon Twaddle. Positioning: plain English, big type, no clutter, real numbers with a date on them.

It is not a senior site. It is a site a tired person can use without a hobby.

It is not a free advice hotline. No public phone number that reaches Jon. Email is corrections and press only. Issuer 800 numbers on card boxes are fine.

Money: affiliate / referral links on Apply. Never sort or rank by what pays. Disclosure stays at the top of pages with links and under every Apply button.

Do not copy Bankrate’s wall of Apply buttons, TPG’s points homework, NerdWallet’s 12 “top ___ cards” links before the reader has answered anything, popups, sticky bars, carousels, or AI summaries.

The product, in one screen

There is no “best credit card.” There is a best first card for this person.

Ask three things (spend form already does the math):

1. Pay in full, or carrying a balance?
2. Groceries, or everything?
3. Will they pay an annual fee if it earns it back?

Then show one winner and one runner-up. One Apply button each. That is above the fold.

The engine already lives at /apply/ (public/js/desk-engine.js + card JSON). Homepage should be that product, not a magazine.

The card offer box (the unit)

Same field order every time so it feels like one system:

1. Name, issuer, network, our rating /5
2. Annual fee
3. Welcome offer with spend requirement in plain sight
4. Rewards as a person would say them (“3% at US supermarkets, up to $6,000 a year, then 1%”)
5. Intro APR if any. Regular APR, with “APR is the yearly interest rate if you carry a balance”
6. Foreign fee. Credit needed. Best for. Skip it if.
7. One button: “Apply on [Issuer]’s site” → must keep href="/go/{slug}/"
8. One-line disclosure under the button
9. “Checked by hand on [date]” + offer history in a <details>

Amex boxes also need Rates & Fees, “Terms apply,” and “Welcome offers vary…”

Do not add a second Apply. Do not add “our partners” ribbons. Do not hide the spend requirement.

Visual system

Already in src/styles/global.css. Improve it; do not throw it out.

• Light background default. High-contrast toggle, not a dark-mode toggle.
• Body 18px min, text-size control 18 / 20 / 22, saved in localStorage (tpd-textsize, tpd-contrast).
• Contrast 7:1 body. No light gray text. Never meaning by color alone.
• Links blue and underlined. Visited links change color.
• Buttons look like buttons. 48px tap targets, 8px gaps.
• Serif headings, humanist sans body, navy primary (#1e3a5f), one accent, white / off-white surfaces.
• Max content width ~1080px. Prose measure ~68ch.
• Tables scroll inside their own box, never the page.
• Print stylesheet (people print this).
• No popups, interstitials, carousels, sliders, autoplay, sticky convert bars, hover-only nav, third-party pixels, or cookie banners.

Reader controls already live in ReaderControls.astro. Keep them visible in the header.

Voice (UI copy)

Short sentences. One idea per paragraph. About 7th-grade level.

• Recommend, then say who should skip.
• Define jargon in the same sentence the first time.
• No em dashes. No emoji. No exclamation points. No “delve / robust / seamless / unlock.”
• Never “best” without “best for whom.”
• Never first-person “we tested” unless Jon said he did.

There is a writing linter: npm run lint. Copy you add in .astro files must pass it.

Apply tool UX (/apply/)

Keep the existing JS engine. Improve layout:

• Left or top: the form (spend fields, fee, credit, checkboxes, cards I already have)
• Right or below: live results in an aria-live region
• Pick card is a large offer-style panel. Runner-up is secondary, not equal.
• Rank is ongoing year first, then year one. Do not change that logic.
• Show: “Year one you keep about $X. A normal year after that: $Y.”
• Apply still goes to /go/{slug}/
• Prefill from query params (groceries, other, feeMax) so the homepage form works

Nothing the user types may be posted to a server.

What “done” looks like

1. Homepage answers “best credit card?” in one screen (form + four doors).
2. /apply/ looks like the flagship product, not a form from 2009.
3. Card boxes are consistent and scannable on phone.
4. Compare-two is obvious from Cards and Tools.
5. Footer has email, not a “call Jon” line.
6. npm run lint and npm run build pass.
7. No new tracking scripts. No new fonts from Google if they need a network.

Do not

• Add medical-alert / hearing-aid / home-security as top nav
• Add a phone number for Jon
• Rank cards by affiliate payout
• Generate 90 thin comparison URLs
• Clone NerdWallet’s HTML, ratings, or sentences
• Invent Jon’s wallet holdings or “I have this card” lines
• Break /go/{slug}/ or change apply URLs to skip it

Suggested build order

1. Global layout: header, nav, footer, type, buttons, offer box
2. Homepage (form + four doors)
3. /apply/ results layout
4. /cards/ hub + review/best templates
5. /cards/compare/ and /wallet/ and /offers/
6. Guides + trust pages last (same chrome, quieter)

If something in the data or engine is unclear, read AGENTS.md, src/site.ts, src/components/OfferBox.astro, and public/js/desk-engine.js. Do not invent new card numbers.
